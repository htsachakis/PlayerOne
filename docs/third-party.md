# Third-party software in PlayerOne

PlayerOne is a front end. The work of decoding video is done by **mpv**, and
subtitle extraction and file inspection by **ffmpeg** and **ffprobe**. Both are
separate programs, invoked as child processes — no third-party code is linked
into PlayerOne's executable.

## What is distributed

| Component | Licence | How PlayerOne uses it |
|---|---|---|
| [mpv](https://mpv.io) | GPLv2 or later (the Windows builds are GPL) | Run as a child process. Controlled over its JSON IPC socket; renders into a window PlayerOne provides. |
| [FFmpeg](https://ffmpeg.org) (`ffmpeg`, `ffprobe`) | GPLv2 or later for the GPL builds used here | Run as child processes to convert a subtitle track to text and to read file details. |
| [Wails](https://wails.io) | MIT | Go/WebView2 application framework, compiled in. |
| [go-winio](https://github.com/microsoft/go-winio) | MIT | Windows named-pipe client for the mpv IPC connection. |
| [Vite](https://vite.dev), [TypeScript](https://www.typescriptlang.org) | MIT / Apache-2.0 | Build tooling for the interface. |

## What this means if you redistribute PlayerOne

The release packages **bundle mpv and ffmpeg binaries**, and those are GPL. If
you redistribute a package that contains them, the GPL obligations travel with
them: recipients must be able to obtain the corresponding source for those
binaries.

The practical way to satisfy this is to keep pointing at the upstream sources
the binaries were built from:

* mpv Windows builds: <https://github.com/shinchiro/mpv-winbuild-cmake>
  (the build scripts, and the mpv and FFmpeg sources they fetch)
* mpv source: <https://github.com/mpv-player/mpv>
* FFmpeg Windows builds: <https://github.com/BtbN/FFmpeg-Builds>
* FFmpeg source: <https://github.com/FFmpeg/FFmpeg>

`scripts/fetch-tools.ps1` downloads exactly these binaries and prints their
versions, so the release always matches a published upstream build.

PlayerOne's own source is in this repository.

## Building without bundling

Because PlayerOne only ever *runs* these tools, and finds them on `PATH` when
they are not in `bin/`, it can be distributed without them. Do not run
`scripts/fetch-tools.ps1`, and do not include `bin/` in the package; PlayerOne
will then explain what is missing and where to put it the first time it starts.

## Assets

The application icon and wordmark are original work generated by
`build/branding/make_icons.py`. No third-party artwork is included, and the
interface deliberately does not copy any other player's assets.
